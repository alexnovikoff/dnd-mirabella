# «Слёзы Мирабеллы» — план реализации

Источник требований — `design_handoff_mirabella/README.md` (спецификация) и
`design_handoff_mirabella/Слёзы Мирабеллы v2.dc.html` (визуальный референс).
Прототип — не production-код: inline-стили и статичные данные, его разметка не переносится.

## Решения

|             |                                                                                    |
| ----------- | ---------------------------------------------------------------------------------- |
| Репозиторий | отдельный `dnd-mirabella`, не модуль `dnd-toolbox`                                 |
| Фреймворк   | Next.js 15 App Router + TypeScript                                                 |
| Стили       | CSS Modules + глобальный `src/styles/tokens.css`, без Tailwind и UI-китов          |
| БД          | Neon Postgres + Drizzle (локально — PGlite, тот же диалект)                        |
| Изображения | Vercel Blob                                                                        |
| Вход        | Auth.js, Credentials — пять учёток партии, argon2, без самостоятельной регистрации |
| Node        | ≥ 20.9                                                                             |

Neon-проекта пока нет, поэтому локальная разработка идёт на встроенном PGlite:
те же миграции и тот же диалект, переезд — замена драйвера в `src/lib/db/client.ts`
плюс `DATABASE_URL`. Миграции и сид вынесены в отдельный процесс (`pnpm db:setup`):
PGlite сбрасывает wasm-память на диск, и подготовка базы внутри рендера роняет
первый запрос. Приложение базу только открывает — так же, как будет с Neon.

Отступление от модели README: Character и Entity сведены в общую таблицу `nodes`
с дискриминатором (README это прямо разрешает), детали персонажа — в `characters`.
Ради этого ребро `links` получило настоящие внешние ключи вместо полиморфных id:
ровно один из `from_node_id` / `from_entry_id` заполнен, что закреплено CHECK-ограничением.

Следствие выбора Credentials: сессии только JWT (Auth.js не поддерживает сессии в БД для
этого провайдера). Роль и `characterId` кладутся в токен.

## Известные ограничения

- Запросы в `lib/queries` ходят в базу через `runDb` и завязаны на singleton
  соединения, поэтому юнит-тестами не покрыты — тестируется то, что от базы
  не зависит (разбор `[[ссылок]]`) и то, что принимает `db` параметром
  (`syncEntryLinks`). Развязать стоит, когда запросов станет заметно больше.
- Хоткей быстрой записи — `n`; в спецификации клавиша не названа.
- Тип «ФОТО» в быстрой записи сохраняет только подпись; файлы перетаскивают
  на экран «Галерея». Приём файлов прямо из шита не сделан.
- Загрузка файлов пишет в `public/uploads` локальным драйвером `lib/storage.ts`.
  На Vercel файловая система только для чтения — там драйвер заменит Vercel Blob;
  вызывающий код и колонка `images.url` не меняются.
- Родовые формы («ЗАГРУЗИЛА МЕТЕЛЬ», «Её моменты») из макета заменены нейтральными:
  пол игрока нигде не хранится, а выдумывать это поле не стоит.

## Открытые вопросы

- Переименование сущности: в тексте хранится `[[Имя]]`, у сущности — уникальный slug
  и алиасы. Старое имя уходит в алиасы, поэтому `[[Старое Имя]]` в уже написанных
  записях продолжает резолвиться и ведёт на новый адрес. Слаг переписывается под новое
  имя: алиасы закрывают текст, но не старые URL — прежний адрес показывает «не найдено».
- Удалять сущности может только мастер: узел висит в записях всей партии.
  Персонажа партии удалить нельзя, и тип у него не меняется.
- Три размера превью из README не генерируются: `next/image` отдаёт нужные с оригинала.
- Без входа сайт открыт для чтения (решено на этапе 9; ранее предполагалось
  закрыть его целиком).
- Позиции узлов доски — общие на кампанию, не на пользователя.

## Расхождения README ↔ прототип

Канон — README (объявлен источником истины по значениям). Варианты прототипа заведены
рядом под своими именами в `tokens.css`, решение по ним за владельцем.

Штриховка оказалась не расхождением, а параметром: прототип использует шаги 5, 6, 7 и 8 px
для аватаров, сайдбара, карточек и плиток галереи. `--hatch` параметризован `--hatch-step`,
значение по умолчанию совпадает с README.

| Что             | README                                   | Прототип                               |
| --------------- | ---------------------------------------- | -------------------------------------- |
| фон карточки    | `--card-bg`, 3 стопа (1 вхождение)       | `--card-bg-2`, 2 стопа (9 вхождений)   |
| мета на акценте | `--accent-on-dim` `#e8bda6`              | `#f0c8b3` в карточке цитаты на Хронике |
| тень листа      | `--sheet-shadow` без внутренней засветки | плюс `--sheet-shadow-inset`            |
