# «Слёзы Мирабеллы» — план реализации

Источник требований — `design_handoff_mirabella/README.md` (спецификация) и
`design_handoff_mirabella/Слёзы Мирабеллы v2.dc.html` (визуальный референс).
Прототип — не production-код: inline-стили и статичные данные, его разметка не переносится.

Сайт развёрнут на Vercel 9 сентября 2026 (PR #1–#2). Всё, что сделано после, —
в разделе [После запуска](#после-запуска); решения, которые расходятся со
спецификацией, — в [Отступлениях от хендоффа](#отступления-от-хендоффа).

## Решения

|             |                                                                                    |
| ----------- | ---------------------------------------------------------------------------------- |
| Репозиторий | отдельный `dnd-mirabella`, не модуль `dnd-toolbox`                                 |
| Фреймворк   | Next.js 15 App Router + TypeScript                                                 |
| Стили       | CSS Modules + глобальный `src/styles/tokens.css`, без Tailwind и UI-китов          |
| БД          | Neon Postgres + Drizzle (локально и в CI — PGlite, тот же диалект)                 |
| Изображения | Vercel Blob (локально — public/uploads)                                            |
| Вход        | Auth.js, Credentials — пять учёток партии, argon2, без самостоятельной регистрации |
| Node        | ≥ 20.9                                                                             |

Драйвер выбирается по окружению, а не по сборке: есть `DATABASE_URL` — Neon,
нет — встроенный PGlite в `.pglite` (локальная разработка и CI). То же с файлами:
есть `BLOB_READ_WRITE_TOKEN` или `BLOB_STORE_ID` (хранилище подключено к проекту
через OIDC) — Vercel Blob, нет ни того, ни другого — `public/uploads`. Слой запросов
и вызывающий код о выборе не знают.
Миграции и сид вынесены в отдельный процесс (`pnpm db:setup`):
PGlite сбрасывает wasm-память на диск, и подготовка базы внутри рендера роняет
первый запрос. Приложение базу только открывает — так же, как с Neon.

Отступление от модели README: Character и Entity сведены в общую таблицу `nodes`
с дискриминатором (README это прямо разрешает), детали персонажа — в `characters`.
Ради этого ребро `links` получило настоящие внешние ключи вместо полиморфных id:
ровно один из `from_node_id` / `from_entry_id` / `from_session_id` заполнен, что
закреплено CHECK-ограничением `num_nonnulls(...) = 1`. Узел → узел — ручная связь,
запись → узел и сессия → узел — упоминания из `[[текста]]`.

Следствие выбора Credentials: сессии только JWT (Auth.js не поддерживает сессии в БД для
этого провайдера). Роль и `characterId` кладутся в токен.

## После запуска

Работа после деплоя шла короткими PR (#3–#43, 9–14 сентября). Ниже — что появилось
и какие решения за этим стоят; подробности — в сообщениях коммитов.

### Хроника

- **Анонс следующей игры** над лентой — единственная строка, которая смотрит вперёд.
  Свободный текст (`campaigns.next_game`), а не `date`: «16 сентября (среда), старт
  в 20.00» календарной датой не выражается. Правит любой вошедший; разлогиненному
  пустой блок не показывается.
- Наверху ленты — **случайная цитата** вместо цитаты недели: выбирается на сервере
  при каждом запросе.
- Заголовки блоков сайдбара («Сессии», «Заметки», «Галерея») и «Доска связей» —
  ссылки на свои экраны. У «Сессий», «Заметок» и «Галереи» в шапке блока кнопка
  «+», чтобы завести сессию, заметку или кадр не уходя с главной.
- Виджет «Галерея» показывает сами кадры (штриховка — фон, пока файла нет), шесть
  на странице, страницы листаются стрелками в шапке блока. Дроп-зона из превью
  убрана — кадр добавляет кнопка.
- **Превью доски** выросло до 820×492 (пропорция полотна 5:3), ширина карточки —
  доля канвы, длинные названия режутся двумя строками; узкий экран листает канву
  вбок. Узлы в превью связываются перетаскиванием, как на доске.
- Фильтры ленты — ВСЁ / ЦИТАТЫ / ЛУТ. Пометок «Крит N» и «Провал N» на карточках нет,
  фильтра ПРОВАЛЫ тоже (см. [Решено не делать](#решено-не-делать)).

### Сессии

- Экран **`/sessions`** — все сессии кампании; в сайдбаре помещаются последние пять.
  Число записей считается по тому, что зритель вправе видеть.
- **Пересказ игры** (`sessions.description`) — свободный текст с `[[ссылками]]`,
  пишет и правит любой вошедший. Ссылки заводят рёбра графа наравне с записями
  (источник `links.from_session_id`); имя без сущности можно завести прямо из
  пересказа (`resolveSessionMention`).
- **Удаление сессии** спрятано внутри «Править сессию». Записи, кадры и узлы
  остаются — внешние ключи `on delete set null`, они просто оказываются вне сессий.
  Номера соседних игр не пересчитываются: дыра в нумерации честнее сдвига адресов.
- Дата игры в списке и на карточке сессии — полностью («6 сентября 2025»),
  короткие формы — в шапке сайта и в сайдбаре. Дату ставят в «Править сессию».
- Навигация на карточке сессии: «К списку сессий» и «к Галерее» строкой текста над
  заголовком, под ним «← С11 / С13 →» слева и «Править сессию» справа.
- Сид больше не выдумывает моменты, заметки, кадры и даты: 26 сессий с настоящими
  заголовками, пустые, пока в них не запишут своё.

### Быстрая запись

- **Сессия записи выбирается в шите.** При создании подставляется активная, при
  правке — сессия самой записи; пустой пункт — запись **вне сессий** (арт, карта
  мира, заметка между играми). Кадры фото-записи переезжают вместе с ней.
- Кнопка в шапке открывает шит сразу на типе своего раздела: «+ ЦИТАТА» на
  «Цитатах», «+ ФОТО» на «Галерее». Ширина у неё одна на всех экранах — под самую
  длинную подпись, иначе вкладки сдвигаются при переходах.
- Подпись кадра необязательна, если есть файл; Enter в ней отправляет форму.
  Крестик закрытия — в левом верхнем углу.

### Цитаты

- Цитаты заводятся, правятся и удаляются прямо в цитатнике; последняя ячейка сетки —
  кнопка «+ Цитата» (заглушка «вставить из чата или голоса» была тупиком).
- Все цитаты равноценны: цитаты недели и голосования нет нигде, ни на «Цитатах»,
  ни в «Хронике», ни на странице персонажа.

### Галерея

- Плитка портретная, 3:4; ключевой кадр — те же 2×2. Подпись под плиткой, у ключевого
  кадра — плашкой поверх. Подпись правится по клику; имя файла подписью не становится.
- Кадр снимается крестиком с подтверждением; запись типа «фото» уходит вместе с ним,
  момент, к которому кадр приложен, остаётся.
- Группу для загрузки выбирают над полосой загрузки: активная сессия, любая другая
  или «без сессии». Пачка файлов — это N кадров, каждый своим запросом (см. «Загрузка
  файлов»). Заголовок группы ведёт на страницу сессии.

### Персонажи

- **Персонаж — один тип, основной или гостевой.** Узел «Персонаж» всегда со строкой
  в `characters`, со страницей `/characters/…`, портретом и достижениями.
  `characters.is_pc`: основной (true) виден в «Партии», в hero «Хроники» и среди
  авторов цитат; гостевой (false) — только по тумблеру «Показать гостевых персонажей»
  в «Партии», после основных и с пометкой «Гость».
- Персонаж, заведённый с доски или в базе знаний, и узел, которому сменили тип на
  «Персонаж», становятся **гостевыми**. Основным его делает тумблер «Гостевой
  персонаж» на карточке сущности и на странице персонажа (`setCharacterGuest`).
  Переключает любой вошедший.
- **Тип и удаление закрыты только персонажу с игроком** (`characters.player_id`).
  Остальных можно удалить или перевести в другой тип: портрет, биография и
  достижения при этом пропадают — редактор спрашивает подтверждение, сервер
  убирает строку, кадры-достижения и их файлы.
- Цитату, приписанную гостю, правят не меняя автора: шит добавляет его в список
  авторов только для этой цитаты.
- **Достижения** — блок внизу страницы персонажа: плитки 16:9 с кадром целиком,
  загрузка кнопкой и перетаскиванием, лайтбокс, подпись правится по клику.
  Общие плитки: загрузить, переподписать и снять может любой вошедший.
- **Кадрирование портрета** для карточки в «Партии»: рамка тянется мышью или
  стрелками, кадр режется в браузере и уходит отдельным файлом
  (`characters.portrait_crop_url`, рамка — `portrait_crop`). Портрет как его
  загрузили остаётся в `portrait`, его показывают все остальные экраны.
  Новая загрузка портрета сбрасывает кадр.
- **Галерея персонажа** — кадры, в подписи которых он назван в любом падеже или под
  прежним именем, кто бы их ни загрузил (`lib/name-mentions`: склонение по последней
  букве имени). Достижения и кадры карточек сюда не идут.
- Метрики — моменты, цитаты, связи. Метрики крита нет. «Править» — в верхней
  строке шапки, рядом с метой.

### База знаний и карточка сущности

- Таб **«Всё»** первым, на голом `/kb`; в нём узлы всех восьми типов, включая
  персонажей партии. «+ Добавить» наверху списка заводит любой тип.
  Под названием карточки — тип узла, статус и счётчик связей.
- Карточка сущности: «← К базе знаний» помнит таб, из которого её открыли; рядом —
  «к доске связей» с этой сущностью уже выбранной. Тип, статус и прежние имена —
  под названием, «Править» — в строке названия.
- **Изображения на карточке**: грузятся кнопкой или перетаскиванием, снимаются
  крестиком, смотрятся в лайтбоксе. Тот же `images.node_id`, что у достижений,
  с видом `entity` — в «Галерею» такие кадры не попадают.
- В формах «+ УЗЕЛ», «+ Добавить» и смены типа есть тип «Персонаж» — узел становится
  гостевым персонажем (см. «Персонажи»). У персонажа на карточке сущности тумблер
  «Гостевой персонаж» и ссылка «к странице персонажа».

### Доска связей

- **Связь перетаскиванием** карточки на карточку — на доске и в превью: открывается
  окно типа связи; повторный дроп той же пары правит связь, а не заводит вторую.
  Дроп в пустоту двигает узел.
- **Масштаб 20–200% шагом 20%**, при смене масштаба центр окна остаётся на месте.
  Вокруг полотна поле по 600px — доску тянут во все стороны; открывается посередине
  на 100%. Расчёт вида — `lib/board-view` с тестами.
- **Размер плитки меняют как у окна.** Вошедший наводит курсор на нижний правый
  угол любой плитки — появляются курсор и три косых штриха — и тянет: ширина (до
  600px) и высота независимы, левый верхний угол стоит, текст переносится по новой
  ширине. Уже самого длинного слова и ниже содержимого плитка не становится — так
  у короткого имени отступы слева и справа выходят равными, а не остаётся пустое
  поле, как при прежнем постоянном минимуме в 90px. Размер общий на кампанию, как
  позиция (`board_positions.width`, `height`, null — по умолчанию). Координаты —
  по-прежнему центр плитки, от него идут линии; при растягивании центр сдвигается
  и пишется вместе с размером, поэтому `x`, `y` дробные (до сотой процента), иначе
  угол уезжал бы на округлении. Без мыши наводить нечем: на сенсорных экранах штрихи
  видны у выбранной плитки, угол крупнее. Превью на «Хронике» размеры не показывает:
  в миниатюре крупные карточки легли бы на соседей.
- **«ПЛИТКИ − 100% +»** под масштабом — множитель зрителя, 60–200% шагом 20%: только
  плитки, узлы стоят где стояли. Кука `board-tile-scale`, сервер сразу рисует доску
  с ней. Логика размеров — `lib/board-tile` с тестами.
- **На телефоне граф остаётся**: окно ниже полотна, листается пальцем, список узлов
  под графом — оглавление.
- Панель узла: первый кадр карточки в своих пропорциях (у персонажа с портретом — портрет),
  «Править» в строке «Выбранный узел», «Связи» и «Упоминания» отбиты от узла.
  Упоминания называют и сессии, в пересказе которых узел назван.
- Линии связей толще; хвоста от карточки к её прежнему месту при перетаскивании нет.

### Права

- **Правит тот, кто видит** — одна функция `canEditEntry` вместо четырёх копий
  проверки: общую запись правит и удаляет любой вошедший, личную заметку и черновик —
  автор и мастер, `dm_only` — мастер. Сервер проверяет то же самое.
- Сущности, достижения, кадры карточек, пересказы сессий, анонс игры — общее хозяйство:
  их заводит, правит и снимает любой вошедший.

### Загрузка файлов

- Файлы едут **по одному** на запрос (`lib/uploads`): отказ касается только своего
  файла и показывается строкой, остальные ложатся, идёт счёт «Загружаем 2 из 5…».
  Так грузят «Галерея», шит, «Достижения» и изображения карточки.
- Предел тела серверного экшена поднят до **4 МБ** (`next.config.ts`): выше не пустит
  Vercel — 4,5 МБ на запрос.

### Данные и эксплуатация

Миграции после деплоя (накатываются на Neon вручную — см. README «Обновление
продакшена»):

| Миграция | Что делает                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------ |
| 0002     | вид кадра `achievement`, колонка `images.node_id`                                                                        |
| 0003     | `sessions.description`                                                                                                   |
| 0004     | `characters.portrait_source` и `portrait_crop` (первая версия кадрирования)                                              |
| 0005     | `characters.portrait_crop_url`                                                                                           |
| 0006     | переносит кадр в `portrait_crop_url`, оригинал — обратно в `portrait`; **удаляет** `portrait_source`                     |
| 0007     | `campaigns.next_game` и первый анонс                                                                                     |
| 0008     | вид кадра `entity`                                                                                                       |
| 0009     | `links.from_session_id`, CHECK на `num_nonnulls(...) = 1`                                                                |
| 0010     | **удаляет** таблицу `votes` и колонки `entries.roll`, `is_crit`, `is_fail` — накатывать после деплоя                     |
| 0011     | узлам «Персонаж» без строки заводит гостевого персонажа; строке без типа возвращает «Персонаж» — накатывать после деплоя |
| 0012     | `board_positions.width` и `height`, `x` и `y` становятся `real` — накатывать до мёржа                                    |

Одноразовые скрипты для боевой базы — показывают изменения, меняют только с `--apply`,
после прогона их можно удалить:

- `pnpm db:resync-sessions` — сносит заглушки прежнего сида по id, чистит даты,
  ставит настоящие заголовки сессий;
- `pnpm db:resync-session-links` — заводит рёбра по пересказам, написанным до 0009.

`hookTimeout` в vitest — 30 с: холодный PGlite с миграциями под нагрузкой не
укладывается в дефолтные 10 с на `beforeEach`.

## Известные ограничения

- Слой запросов покрыт тестами через шов `setDbForTesting`: тест поднимает
  PGlite в памяти, накатывает те же миграции и подменяет соединение.
  Фикстура — `src/lib/db/fixture.ts`, а не боевой сид: нужен предсказуемый
  набор записей, а не вся кампания.
- Хоткей быстрой записи — `n`; в спецификации клавиша не названа.
- Загрузка файлов: `lib/storage.ts` кладёт в Vercel Blob, когда задан
  `BLOB_READ_WRITE_TOKEN` или `BLOB_STORE_ID`, и в `public/uploads` — когда нет. Колонка
  `images.url` одна на оба случая: локальный путь `/uploads/…` или абсолютный
  адрес Blob, по нему же `removeUpload` понимает, чей файл удаляет.
- Один файл — не больше 4 МБ (предел запроса к функции на Vercel — 4,5 МБ).
- Пароли: сид ставит всем один временный (`SEED_PASSWORD`). Свой пароль
  участник меняет на `/account`, чужой сбрасывает мастер скриптом
  `pnpm auth:password` — для сброса нужен доступ к базе, а не чужая сессия.
- Родовые формы («ЗАГРУЗИЛА МЕТЕЛЬ», «Её моменты») из макета заменены нейтральными:
  пол игрока нигде не хранится, а выдумывать это поле не стоит.
- Фильтр ленты ЛУТ смотрит на тег `#лут`, но ни шит, ни экшены теги не заполняют,
  а сид таких записей не создаёт.

## Открытые вопросы

- Переименование сущности: в тексте хранится `[[Имя]]`, у сущности — уникальный slug
  и алиасы. Старое имя уходит в алиасы, поэтому `[[Старое Имя]]` в уже написанных
  записях продолжает резолвиться и ведёт на новый адрес. Слаг переписывается под новое
  имя: алиасы закрывают текст, но не старые URL — прежний адрес показывает «не найдено».
- Удалять сущности может любой вошедший — их и заводят все. Персонажа, к которому
  привязан игрок, удалить нельзя, и тип у него не меняется: у игрока своя учётка и
  «Профиль» в чипе аккаунта. Это про целостность данных, а не про роли. Привязать
  игрока к персонажу из интерфейса нельзя — только в базе.
- Три размера превью из README не генерируются: `next/image` отдаёт нужные с оригинала.
- Без входа сайт открыт для чтения (решено на этапе 9; ранее предполагалось
  закрыть его целиком).
- Позиции и размеры узлов доски — общие на кампанию, не на пользователя. У каждого
  зрителя свои только масштаб и множитель плиток.
- Файлы кадров не удаляются вместе с сессией и записью-моментом: кадры остаются
  в галерее. Вместе с узлом файлы его кадров, достижений и портрета удаляются.
