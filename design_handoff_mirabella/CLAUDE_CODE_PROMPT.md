# Стартовый промпт для Claude Code

Скопируйте блок ниже целиком в Claude Code, находясь в корне репозитория (`dnd-mirabella` или новый пустой проект). Файлы `README.md` и `Слёзы Мирабеллы v2.dc.html` должны лежать рядом — положите папку `design_handoff_mirabella/` в репозиторий.

---

## Промпт 1 — онбординг и план

```
В папке design_handoff_mirabella/ лежит дизайн-хендофф веб-приложения для D&D-кампании
«Слёзы Мирабеллы».

Прочитай:
1. design_handoff_mirabella/README.md — полная спецификация: экраны, токены, поведение, модель данных.
2. design_handoff_mirabella/Слёзы Мирабеллы v2.dc.html — HTML-прототип со ВСЕМИ экранами.
   Это дизайн-референс, а не production-код: там inline-стили и статичные данные.
   Не копируй его разметку — воспроизводи внешний вид средствами этого проекта.

Затем:
- Изучи текущий репозиторий: стек, структуру, роутинг, подход к стилям, наличие бэкенда.
- Скажи, что уже есть и что придётся добавить.
- Предложи план реализации по этапам с оценкой, куда какие файлы лягут.
- Задай мне вопросы, где спецификация допускает несколько решений
  (хранение изображений, провайдер аутентификации, локальная БД или облачная).

Пока ничего не пиши в код — жду план.
```

## Промпт 2 — фундамент

```
Реализуй этап 1: дизайн-фундамент.

1. Подключи шрифты Cormorant Garamond, Spectral, IBM Plex Mono.
2. Перенеси все токены из раздела Design Tokens README в тему проекта
   (CSS-переменные / конфиг Tailwind — как принято в этом репозитории).
   Значения не меняй: акцент строго #9a5a2e, углы прямые (radius 0).
3. Собери оболочку приложения: «стол» #ddd0b2, лист-пергамент max-width 1180px
   с составным фоном --sheet-bg, рамкой #c3ab7f и тенью, глобальную шапку
   с навигацией Хроника · Партия · Галерея · Цитаты · База знаний · Доска связей
   и чипом аккаунта.
4. Заведи роуты-заглушки под все шесть вкладок + /characters/:slug.
5. Сделай переиспользуемые примитивы из спецификации: ParchmentCard, AccentQuoteCard,
   MonoLabel, StatusPill (open/resolved/dead_end), ImagePlaceholder (--hatch), DropZone.

Сверяй результат с прототипом попиксельно: открой HTML-референс и сравни отступы,
размеры шрифтов и цвета.
```

## Промпт 3 — данные и хроника

```
Этап 2: модель данных и экран «Хроника».

1. Реализуй схему из раздела Data model README (Campaign, Session, Character, Entity,
   Entry, Image, Link, Vote, BoardPosition). Связи Link — ядро продукта, ребро несёт kind
   mention|manual.
2. Засей БД данными кампании из прототипа: партия (Аэлис, Джаду, Метель, Оген),
   сессии 10–14, сущности (Визирь Ирсаф, Дом Сарраф, Колодец Соляных путей, Вторая слеза,
   Аукцион в Ксаире, Печать восьми лучей, Мать Мирабеллы, Караван на север,
   Слепой картограф — тупик), моменты и цитаты из макета.
3. Собери экран «Хроника»: hero с партией, лента моментов с фильтрами
   (всё/цитаты/провалы/лут), сайдбар (сессии, заметки со статусами, превью галереи),
   превью доски связей внизу.
```

## Промпт 4 — редактор и wiki-ссылки

```
Этап 3: быстрая запись и wiki-ссылки — главная механика продукта.

1. Рендер `[[Имя]]` в тексте: ссылка цвета #9a5a2e с точечным подчёркиванием,
   ведёт на страницу сущности, hover #7f4522.
2. Редактор: ввод `[[` открывает автодополнение по всем сущностям (подстрока,
   регистронезависимо), навигация стрелками, Enter подставляет, последняя опция
   «+ создать «<набранное>»» создаёт черновую сущность и сразу связывает.
   Внешний вид панели — см. мобильный экран «Быстрая запись» в прототипе.
3. Каждая ссылка создаёт ребро Link(kind: mention); удаление ссылки из текста удаляет ребро.
4. Модалка быстрой записи: типы момент/цитата/фото/заметка, привязка к активной сессии,
   кнопки «Черновик» и «В хронику».
```

## Промпт 5 — остальные экраны

```
Этап 4: экраны по спецификации README, в порядке:
1. База знаний — заметки и наводки со статусами, подтабы Заметки / NPC / Локации.
2. Галерея — единая лента, сгруппированная по сессиям, с тумблером группировки,
   ключевым кадром span 2×2, лайтбоксом и drag-and-drop загрузкой в текущую сессию.
3. Цитаты — сетка, цитата недели (span 2, на акценте), голосование «♦ N»,
   фильтр по автору.
4. Доска связей — SVG-рёбра под узлами, перетаскивание с сохранением позиций
   в процентах, панель выбранного узла со связями и упоминаниями,
   горизонтальный скролл при ширине < 900px.
5. Страница персонажа — метрики, его моменты и цитаты, связи с типами отношений,
   личная заметка (видна только владельцу и мастеру).
```

## Промпт 6 — аутентификация, роли, адаптив

```
Этап 5:
1. Аутентификация: разлогиненное состояние — кнопка «Войти» в шапке, контент только
   для чтения; вошедший — чип с аватаром и именем персонажа, меню (профиль, выход).
2. Роли: игрок (пишет свои записи, видит общее и свои личные заметки) и
   мастер (видит и правит всё, помечает записи скрытыми от игроков).
   Провайдер выбери сам под стек и объясни выбор.
3. Адаптив по README: ≥1024 — как в макете; 768–1023 — сайдбар под контент,
   галерея 3 колонки; <768 — один столбец, мобильная шапка с горизонтальными табами,
   закреплённая кнопка «+ Быстрая запись», доска связей заменяется списком.
   Минимальная зона касания 44px.
4. Состояния: скелетоны в тон пергамента (#e2d4b0), пустые состояния в стиле дроп-зон,
   ошибки на акценте. Переходы 120–160ms ease-out, ничего более резкого —
   дизайн намеренно «бумажный».
```

## Заметки на всякий случай

- **Не отдавайте HTML-референс в продакшн.** Это прототип: inline-стили, статичные данные, состояния показаны «вручную» (активные табы, автодополнение, вошедший аккаунт).
- **Цвета и типографика финальные.** Если Claude Code предложит «улучшить» палитру или скруглить углы — не соглашайтесь: прямые углы и жжёная охра #9a5a2e держат весь стиль.
- **Плейсхолдеры изображений намеренные.** Штриховка с mono-подписью показывает, что за картинка там ожидается. Заменяйте на реальные арты кампании.
- **Главная фича — граф.** Если урезать проект, режьте голосование за цитаты и мобильный адаптив, но не `[[wiki-ссылки]]` и не доску связей: без них это обычный блог.
