# Handoff: Слёзы Мирабеллы — веб-страница кампании D&D

## Overview
Веб-приложение для группы D&D: партия ведёт хронику ярких моментов, цитатник, галерею изображений, базу знаний (заметки/наводки с wiki-ссылками) и доску связей между сущностями. Кампания — «Слёзы Мирабеллы»: пустынно-восточный сеттинг, семь артефактов, исполняющих желания. Партия: Аэлис (дженази, плут/монах), Джаду (табакси, волшебник), Метель (тифлинг, плут), Оген (дженази, плут/чародей).

Ключевая идея продукта: **любая запись может ссылаться на любую сущность**. Ссылки ставятся из текста синтаксисом `[[Имя]]` и одновременно образуют граф, который виден на «Доске связей».

## About the Design Files
Файлы в этом бандле — **дизайн-референсы, сделанные в HTML**. Это прототипы, показывающие задуманный вид и поведение, а **не production-код для копирования**. Задача — воспроизвести эти экраны в целевой кодовой базе средствами её собственного окружения (React/Vue/Svelte/Next и т.п.), используя её существующие паттерны, роутинг и библиотеки. Если окружения ещё нет (пустой репозиторий), выберите стек сами — рекомендация ниже в разделе «Предлагаемый стек».

Разметка в референсах — inline-стили и статичные данные; это артефакт инструмента прототипирования, а не рекомендация по архитектуре. При переносе выносите значения в токены/тему, а данные — в модель.

## Fidelity
**High-fidelity.** Цвета, типографика, отступы и композиция финальные — их следует воспроизводить точно (значения ниже). Не финализировано и требует решений разработчика:
- реальная интерактивность (в прототипе состояния показаны статично: активные табы, автодополнение `[[…]]`, вошедший аккаунт);
- перетаскивание узлов на доске связей и алгоритм раскладки;
- загрузка файлов, хранение изображений, аутентификация (в макете — только UI);
- адаптив между 390 px и 1180 px (в макете зафиксированы две точки: мобильная 390 px и десктоп ≤1180 px).

## Предлагаемый стек (если репозиторий пустой)
- React + TypeScript + Vite; роутинг — React Router.
- Данные: любой backend с реляционной моделью (Postgres + Prisma) — модель ниже графовая по сути, но плоских таблиц со связями достаточно.
- Стили: CSS-переменные из раздела «Design Tokens» + CSS Modules или Tailwind с кастомной темой. Никаких UI-китов с собственной эстетикой — дизайн специфичен (пергамент), готовые компоненты будут мешать.
- Изображения: объектное хранилище (S3-совместимое) + превью 3 размеров (thumb 160, grid 480, full).

## Interactions & Behavior

**Навигация.** Шесть вкладок = шесть роутов: `/` (хроника), `/party`, `/gallery`, `/quotes`, `/kb`, `/board`. Плюс `/characters/:slug` и `/sessions/:n`. Активная вкладка подчёркивается акцентом.

**Wiki-ссылки `[[Имя]]`.** Главный механизм.
- В редакторе: ввод `[[` открывает автодополнение по всем сущностям (персонажи, NPC, фракции, локации, артефакты, события, заметки, сессии). Совпадение по подстроке, регистронезависимо; первая строка выделена; Enter/клик подставляет; последняя опция — «+ создать «<набранное>»», создаёт черновую сущность типа «неизвестно» и сразу связывает.
- В рендере: ссылка — цвет `#9a5a2e`, `border-bottom: 1px dotted`; hover — цвет `#7f4522`; клик ведёт на страницу сущности. Наведение в идеале даёт поповер с описанием (nice-to-have).
- Каждая `[[ссылка]]` создаёт ребро графа с типом `mention`; удаление ссылки из текста удаляет ребро.

**Доска связей.** Узлы перетаскиваются, позиция сохраняется per-user или per-campaign (решить: рекомендую per-campaign, доска общая). Клик по узлу — панель справа. «Связать с узлом…» — выбор второй сущности и типа связи (ручное ребро, в отличие от `mention`). Линии перерисовываются за узлами (SVG слоем ниже). Горизонтальный скролл при ширине < 900px; на мобильном граф заменяется списком.

**Быстрая запись.** Модалка/шит, открывается кнопкой «+ Запись» и по хоткею. Тип записи переключается табами; поля меняются под тип (для ФОТО — дроп-зона, для ЦИТАТЫ — автор + текст). «Черновик» сохраняет без публикации в ленту (виден только автору), «В хронику» публикует. Запись всегда привязывается к активной сессии.

**Галерея.** Drag-and-drop на страницу целиком (подсветить дроп-зону при `dragover`), загрузка в текущую сессию, прогресс на плитке. Клик — лайтбокс с подписью, автором загрузки и связанными сущностями. Тумблер группировки переключает `по сессиям` ↔ `по дате`.

**Голосование за цитату.** Один голос на пользователя на цитату, счётчик «♦ N»; цитата недели — максимум голосов за 7 дней, кэшировать.

**Аутентификация.** Разлогинен: кнопка «Войти» в шапке, контент только для чтения (или превью-режим — решить). Вошёл: чип с аватаром и именем персонажа, меню (профиль персонажа, выход). Роли: **игрок** (пишет свои записи, видит общее + свои личные заметки), **мастер** (видит и правит всё, может помечать заметки как скрытые от игроков). Личные заметки на странице персонажа видны только владельцу и мастеру.

**Состояния.** Загрузка — скелетоны в тон пергамента (`#e2d4b0`), без спиннеров. Пусто — плейсхолдеры в стиле дроп-зон с подсказкой действия. Ошибка — плашка на акценте `#9a5a2e`. Все ховеры мягкие: 120–160 ms `ease-out`, сдвиг тени карточки на 1px и лёгкое осветление фона; анимаций больше нигде нет — дизайн намеренно «бумажный».

**Адаптив.** ≥1024px — двухколоночные сетки как в макете. 768–1023px — сайдбар уходит под контент, сетка галереи 3 колонки, сетка цитат 2. <768px — всё в один столбец, шапка → мобильный паттерн (табы горизонтальным скроллом, закреплённая нижняя кнопка), доска → список сущностей. Минимальная зона касания 44px.

## State Management
- `session` — текущий пользователь, роль, привязанный персонаж.
- `activeSession` — номер и дата текущей игровой сессии (влияет на привязку новых записей).
- `filters` — по экрану: лента (все/цитаты/провалы/лут), цитаты (автор), галерея (тип + группировка), база знаний (подтаб + статус).
- `quickEntry` — открыт/закрыт, тип, черновик полей, состояние автодополнения (запрос, кандидаты, выбранный индекс).
- `board` — позиции узлов, выбранный узел, режим связывания.
- `lightbox` — открытое изображение и индекс в группе.
Серверные данные (сущности, записи, изображения, связи) — через кэширующий слой (React Query/SWR): инвалидация по сессии и по сущности.

## Data model (минимум)
- `Campaign(id, title, setting)`
- `Session(id, number, date, title, location)`
- `Character(id, name, race, classes, level, portrait, bio, isPC, playerId)`
- `Entity(id, type: npc|faction|location|artifact|event|rumor, name, description, status: open|resolved|dead_end|null)` — персонажи тоже участвуют в графе, можно вынести в общий `Node` с дискриминатором.
- `Entry(id, sessionId, kind: moment|quote|note|image, title, body, authorId, subjectId, meta{roll, isCrit, isFail}, visibility: public|draft|private|dm_only, createdAt)`
- `Image(id, sessionId, entryId?, url, caption, uploaderId, kind: art|map|screenshot)`
- `Link(id, fromId, toId, kind: mention|manual, label, createdAt)` — ребро графа.
- `Vote(entryId, userId)` — голоса за цитаты.
- `BoardPosition(nodeId, x, y)` — проценты, чтобы граф масштабировался.

## Assets
Собственных изображений в макете нет — **все изображения намеренно плейсхолдеры** (штриховка `--hatch` + mono-подпись, чего там ждать). Иконок-библиотек тоже нет: `+`, `≡`, `←`, `×`, `▾`, `→`, `♦`, `◊` — типографические символы. При реализации:
- поставьте реальные арты/карты кампании в галерею и портреты персонажей;
- если нужны иконки — берите тонкий линейный сет (1.5px, без заливок), чтобы не спорить с бумажной эстетикой; либо оставьте типографику;
- шрифты подключаются с Google Fonts (см. выше) или самохостом.
