# Слёзы Мирабеллы

Сайт кампании D&D: хроника ярких моментов, цитатник, галерея, база знаний и доска
связей. Ключевая механика — `[[wiki-ссылки]]`: любая запись ссылается на любую
сущность, и эти ссылки одновременно образуют граф.

Спецификация и визуальный референс лежат в `design_handoff_mirabella/`,
план работ и решения — в [docs/plan.md](docs/plan.md), правила работы для
Claude Code — в [CLAUDE.md](CLAUDE.md).

## Стек

Next.js 15 (App Router) · TypeScript · CSS Modules · Drizzle · Postgres.

Продакшен — Vercel: Postgres в [Neon](https://neon.tech), картинки в Vercel Blob.
Локально и в CI то же приложение поднимает встроенный [PGlite](https://pglite.dev)
(тот же диалект и те же миграции) и кладёт файлы в `public/uploads/`. Что именно
включится, решают две переменные окружения — см. [Продакшен](#продакшен).

## Запуск

Нужен Node ≥ 20.9 и pnpm.

```bash
pnpm install
cp .env.example .env                              # и вписать AUTH_SECRET
openssl rand -base64 32                           # чем его заполнить
pnpm db:setup   # миграции + сид кампании; обязательно до первого запуска
pnpm dev        # http://localhost:3000
```

Учётки заводит сид: **Аэлис, Джаду, Метель, Оген** (игроки) и **Мастер**.
Пароль у всех один — значение `SEED_PASSWORD`, по умолчанию «мирабелла».
Он временный: свой пароль каждому ставит мастер (`pnpm auth:password «Имя»`),
а сам участник меняет его на `/account`. Самостоятельной регистрации нет.

`pnpm db:setup` выполняется отдельным процессом намеренно: PGlite сбрасывает свою
wasm-память на диск, и миграция, запущенная внутри рендера, роняет первый запрос.
Приложение базу только открывает — так же, как будет подключаться к Neon.

**После `pnpm db:reset` дев-сервер надо перезапустить.** Он держит открытое
соединение с удалённой папкой и продолжит отдавать старые данные.

## Команды

```bash
pnpm dev          # дев-сервер
pnpm build        # продакшен-сборка (нужна готовая .pglite)
pnpm lint         # eslint
pnpm typecheck    # tsc --noEmit
pnpm format       # prettier --write
pnpm db:generate  # сгенерировать миграцию по схеме
pnpm db:setup     # применить миграции и засеять
pnpm db:reset     # снести .pglite и засеять заново (всегда локально)
pnpm test         # vitest
pnpm format:check # то же, что проверяет CI
pnpm auth:password «Имя»  # сменить пароль участнику (ввод скрытый)
pnpm db:resync-sessions       # разово: убрать заглушки прежнего сида из боевой базы
pnpm db:resync-session-links  # разово: рёбра по пересказам, написанным до 0009
```

Оба `db:resync-*` сначала показывают, что изменится, и меняют только с `--apply`.

## Продакшен

Кода переезд не касается: драйверы выбираются по переменным окружения.

| Переменная              | Пусто (локально, CI)          | Заполнено (продакшен) |
| ----------------------- | ----------------------------- | --------------------- |
| `DATABASE_URL`          | встроенный PGlite в `.pglite` | Neon                  |
| `BLOB_READ_WRITE_TOKEN` | файлы в `public/uploads`      | Vercel Blob           |

Хранилище на Vercel подключается к проекту через OIDC — тогда вместо токена
появляется `BLOB_STORE_ID`, а токен SDK получает и обновляет сам. Драйвер
считает Blob подключённым по любой из двух переменных.

Порядок разворачивания:

1. **Neon.** Создать проект, взять pooled-строку подключения
   (хост вида `…-pooler.<регион>.aws.neon.tech`).
2. **Миграции и сид** — разово, с локальной машины:

   ```bash
   DATABASE_URL='<строка Neon>' pnpm db:setup
   ```

   Строка — секрет: в репозиторий она не попадает, в `.env` держать её стоит
   только пока правишь боевую базу (иначе `pnpm dev` будет ходить в Neon).
   `pnpm db:reset` `DATABASE_URL` игнорирует и всегда пересевает локальный PGlite.

3. **Vercel.** Импортировать репозиторий. В Storage создать **публичное**
   хранилище Blob (режим доступа задаётся при создании и не меняется — код
   грузит файлы с `access: 'public'`) и подключить к проекту: переменные
   появятся сами.
4. **Переменные проекта** (Production и Preview): `AUTH_SECRET`
   (`openssl rand -base64 32`, отдельный от локального) и `DATABASE_URL`.
   Смена `AUTH_SECRET` разлогинивает всех. Отдельно — `NEXT_PUBLIC_SHOW_PREVIEW_BADGE=1`
   **только** для Preview и Development: метка PREVIEW в углу, чтобы превью
   не путали с боевым сайтом. Значение вшивается при сборке — после правки
   переменной нужен новый деплой.
5. **Пароли.** Сид ставит всем один временный. Каждому свой:

   ```bash
   DATABASE_URL='<строка Neon>' pnpm auth:password Метель
   ```

6. **Рёбра старых пересказов** — разово, после миграции `0009`. Описания
   сессий умели `[[ссылки]]` раньше, чем те стали заводить рёбра графа;
   пересчёт по уже написанным текстам:

   ```bash
   DATABASE_URL='<строка Neon>' pnpm db:resync-session-links          # предпросмотр
   DATABASE_URL='<строка Neon>' pnpm db:resync-session-links --apply
   ```

### Обновление продакшена

Vercel сам собирает каждый пуш в `main`, а миграции на Neon сборка не накатывает —
это ручной шаг. Если в PR есть новый файл в `drizzle/`:

```bash
DATABASE_URL='<строка Neon>' pnpm db:setup   # миграции; сид на засеянную базу не ляжет
```

Порядок зависит от миграции:

- **добавляет** колонку (nullable или с default), таблицу или значение enum — накатить
  **до** мёржа: старый код новых колонок не замечает, новый без них упадёт;
- **удаляет или переименовывает** — сначала задеплоить код, который их уже не
  читает, и только потом накатить. Иначе упадёт работающий продакшен.

## Доступ

Без входа сайт открыт **только для чтения**: видны публичные записи, но нет
кнопки записи и загрузки, а узлы на доске и в превью на «Хронике»
не двигаются и не связываются перетаскиванием.

Роли:

- **игрок** — ведёт хронику наравне со всеми: правит и удаляет любую общую
  запись, не только свою. Видит общее плюс свои личные заметки и черновики;
- **мастер** — видит и правит всё, включая скрытое от игроков, и может помечать
  новую запись как «скрыть от игроков» (`visibility: dm_only`).

Право на правку одно, и его считает `canEditEntry`: **правит тот, кто видит**.

| Видимость                  | Кто видит          | Кто правит     |
| -------------------------- | ------------------ | -------------- |
| `public`                   | все, включая гостя | любой вошедший |
| `private` — личная заметка | автор и мастер     | автор и мастер |
| `draft` — черновик         | автор и мастер     | автор и мастер |
| `dm_only`                  | мастер             | мастер         |

Достижения персонажа и изображения на карточке сущности — общие плитки:
загрузить и снять их может любой вошедший, как и править общую запись.

Персонажи бывают **основными** и **гостевыми** (`characters.is_pc`). Гостевой не
виден в «Партии» (там его показывает тумблер «Показать гостевых персонажей»),
в hero «Хроники» и среди авторов цитат. Узел, которому дали тип «Персонаж», сначала
гость; переводит его в основные любой вошедший — тумблером на карточке сущности
или флажком в форме правки на странице персонажа. Удалить персонажа или сменить
ему тип можно, пока к нему не привязан игрок.

Пароль хранится argon2id-хешем. Свой меняется на `/account`; чужой сбрасывает
мастер скриптом `pnpm auth:password` — для этого нужен доступ к базе, а не
просто вход в чужую сессию.

Провайдер — Auth.js с Credentials: сайт закрыт для пяти человек, все учётки
заводит мастер. Внешний OAuth добавил бы настройку приложения ради задачи,
которую решает список из пяти строк в базе. Следствие: сессии только JWT —
Credentials не поддерживает сессии в БД. Discord-провайдер можно добавить
рядом позже, учётки не поменяются.

## Дизайн

Все значения — в `src/styles/tokens.css`, перенесены из раздела Design Tokens
хендоффа без изменений. Акцент строго `#9a5a2e`, углы прямые (`--radius: 0`).
Служебный экран `/styleguide` показывает примитивы и токены рядом — по нему
удобно сверяться с прототипом.
